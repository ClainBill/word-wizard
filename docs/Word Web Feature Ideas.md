# Bugs
 - [ ] In the crossword screen the text in the top left says the size and then crossword, but it just get's cut off after the size so have it just display "Mini", "Midi", or "Mega"
 - [x] If you start filling out a crossword and hit back the edits are gone until you close and reopen the app.
   - **Fixed:** `crosswordSessionProvider` (lib/app/providers.dart) was a plain `FutureProvider.family`, so once a puzzle loaded, Riverpod cached that session object forever — including its stale `progress` snapshot from before you started typing. Progress was actually being saved to the database on every keystroke, but going back and reopening the same puzzle just re-served the old cached object instead of re-reading it. Made the provider `autoDispose` so it's dropped when the screen stops watching it, forcing a fresh read from the database (with the saved progress) next time it's opened. Verified in the emulator: filled in letters, backed out, reopened — letters persisted.
 - [x] After opening another puzzle from history the back arrow will just spit you back to the history screen which means you can fall down the rabbit hole of opening a puzzle, looking at its history, opening another puzzle, and so on which will lead to having to hit back arrow a dozen times to get back to the main menu
   - **Fixed:** opening a puzzle from history (lib/features/games/crossword_history_screen.dart) used `context.push`, stacking a new crossword screen on top of the history screen every time, which sat on top of whatever crossword screen was already there — two pushes per hop with no cap. Changed it to pop the history screen and then replace the crossword screen underneath it, so the stack stays exactly one crossword screen deep no matter how many times you hop between a puzzle and its history. Verified in the emulator through two history hops: one back press now returns straight to the Games list.
 - [x] Notifications don't work
   - **Fixed:** the app's AndroidManifest.xml declared the boot receiver (`ScheduledNotificationBootReceiver`) but not the actual firing receiver (`ScheduledNotificationReceiver`) that flutter_local_notifications needs registered to deliver a scheduled notification when its alarm goes off. Without it, AlarmManager still fired the alarm (it even counted as a "wakeup" in dumpsys) but Android had no registered component to hand the broadcast to, so nothing was ever posted — completely silently, no crash, no log. Added the missing `<receiver>` declaration. Also hardened `NotificationService.scheduleDailyReminders` to check `canScheduleExactNotifications()` first and fall back to an inexact schedule when exact-alarm permission isn't granted, since that had been throwing and silently cancelling the whole run. Verified end-to-end in the emulator (temporarily shortened the fire time to confirm delivery, then reverted): the daily-word notification now actually appears in the shade.

  - Fixed two bugs surfaced while building this: the definition-match query was doing `ORDER BY RANDOM()` over the full 700k-row senses table (multi-second stall) — rewritten to a single indexed batch lookup; and the options row was invisible in some layouts due to a Flutter `CrossAxisAlignment.stretch` + unbounded-height interaction (no error, just blank) — fixed with `IntrinsicHeight`.
  - **More recall-jog game ideas (researched, not yet built)** — same constraints as above: never show the headword, force the user to actually generate it from memory (not just recognize it in a list), tiny footprint under the flipped card, done in well under 30s.
    - **Where these come from:** speech-language pathology's "cueing hierarchy" for word-finding therapy (anomia treatment — Tactus Therapy's Naming/Describe apps, Semantic Feature Analysis, Phonological Component Analysis) runs cues least-to-most helpful in two separate families — *semantic* (what it means/relates to) and *phonological* (what it sounds like). Our two built games (definition multiple-choice, spelling scramble) are both semantic-side. Tip-of-the-tongue research (Meyer & Bock 1992; a 2010 *Memory & Cognition* TOT study) found phonological cues actually resolve real tip-of-the-tongue states *better* than semantic ones — in a true TOT state you already know the meaning, you're missing the sound shell, not the concept. That argues for adding a phonological game, not just more semantic variants.
    - **Feature clues** (Semantic Feature Analysis, adapted): show 2-3 short clues about the word — its category, a typical collocation/context, an associated feeling — that circle the meaning without paraphrasing the definition. User free-types a guess (matched loosely against the headword and its inflections) before the answer is revealed either way. Unlike the existing multiple-choice game this forces *generative* recall, not recognition.
    - **Rhyme/sound ladder** (the missing phonological game): reveal syllable count plus "rhymes with ___" (or just the first letter) — nothing about meaning at all. Natural fit as a second attempt after a feature-clue miss, mirroring the clinical semantic-cue-then-phonological-cue order.
    - **Cloze from the word's own example sentence** (this is the fill-in-the-blank idea from the top of this doc — still unbuilt): pull the stored example sentence, blank out the word, size the underscores to word length, user types the answer. Grounds the jog in real usage instead of an abstract definition, and doubles as the "example-sentence" exercise type still open from above.
    - **Letter reveal / "hangman-lite"**: starts fully blank; each tap (or a slow auto-timer) reveals one more letter while the user can submit a guess at any point. Turns the whole cueing hierarchy into one continuous control instead of a menu of separate games, and needs nothing but the headword to build.
    - **Missed-words matching round, at session end rather than per-card**: a single 20-30s drag-to-match grid pairing every word marked "didn't know" that session against its definition — same mechanic as Quizlet's "Match" mode. Only worth showing when a session has more than one miss, so it's a session-end screen, not a per-flip mini-game.
    - **Stretch idea — audio-only cue**: the app already has TTS for pronunciation, so play the audio of a rhyming/similarly-spelled word, or the example sentence with the target word bleeped out, as a sound-only phonological cue. Same shape as Heardle's progressive-reveal-by-listening, just for one word instead of a song.
    - **Deliberately not copying:** Wordle/Connections/Semantle/Contexto-style standalone guessing games are great precedent for "recall without being told the answer," but they're built around a *shared daily puzzle with many sequential guesses*, not a *per-flashcard, single attempt, sub-15s* jog — the core loop doesn't transfer without turning the SRS flip into its own mini session.
